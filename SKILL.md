# devlog

Turns the conversation you just had into a dated log entry and keeps a running map of
how questions led to decisions. Works with any agent that can read and write files.
Nothing runs automatically: the user asks for it ("write today's devlog" / "오늘 일지 써줘").

## Files this skill uses

| Path (in the user's project) | What it is |
|---|---|
| `DEVLOG.md` | User settings: project name, language, tags, things never to record. Created from `templates/DEVLOG.md` on first run. |
| `devlog/YYYY-MM-DD.md` | One entry per day, from `templates/daily.md`. |
| `devlog/map.json` | The rabbit-hole map, from `templates/map.json`. Grows over time. |
| `devlog/dashboard.html` | Optional, generated by `scripts/build_dashboard.py`. |

Read `references/rules.md` before writing anything. Those rules decide what goes in the log.

**Korean (`language: ko`)**: use `references/rules.ko.md`, `templates/daily.ko.md` and
`templates/DEVLOG.ko.md` instead of the English files. `SKILL.ko.md` and `README.ko.md` are
human-readable Korean guides with the same content.

## Steps

1. **Load settings.** Look for `DEVLOG.md` in the project root.
   - If it is missing, copy `templates/DEVLOG.md` there (or `templates/DEVLOG.ko.md` if the
     user writes in Korean), ask the user only for the project name and log language
     (offer sensible defaults), and continue.
   - Respect every line under "Never record" for the rest of the task.
2. **Collect from the conversation only.** Go through this conversation and pull out:
   project work done (results), concepts learned, questions that came up, decisions and their reasons,
   open issues, and the sources consulted. Do not add facts that were not in the conversation
   (see rules.md, rule 4). If something is unclear, leave it out or mark it as open.
3. **Write today's entry.** Open `devlog/<today>.md` if it exists and append a new session
   block; otherwise create it from `templates/daily.md`. Follow rules.md for each section.
4. **Update the map.** Load `devlog/map.json` (create it from `templates/map.json` if missing)
   and add nodes for today: Task → follow-up question → insight → decision. Reuse an existing
   Task node when the work continues one. Keep ids stable; never delete old nodes.
5. **Build the dashboard (if asked, or if `dashboard: auto` in DEVLOG.md).**
   Run `python scripts/build_dashboard.py <project-root>` with the path to this skill's script.
   It needs only the Python standard library and writes `devlog/dashboard.html`.
   If you cannot run commands, tell the user the one command to run themselves.
6. **Report back in two or three lines**: which files changed, and anything you left out
   because it was unclear or on the "Never record" list.

## Keep it short

A day's entry should be readable in two minutes. Prefer one precise line over a paragraph.
If a session had no project work, the Results section says so in one line — don't pad it with study notes.
